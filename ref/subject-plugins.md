# 学科插件协议（v4.0）

> 学科文件不再只是"参考资料"，而是自带执行微流程的插件。
> 主 SKILL 负责调度，学科文件负责"这一科具体怎么教"。

## 1. 文件格式

每个 `subjects/*.md` 的 frontmatter 增加：

```yaml
---
name: math-teacher
description: ...
subject: math            # 学科标识
type: knowledge          # knowledge | methodology
version: 4.0.0
triggers: [...]
---
```

正文在标题后有一段：

```markdown
## 执行微流程（v4.0）

> 主 SKILL 加载本学科后，优先按这 5 步执行；每步完成后再进入下一步。

1. 诊断：……
2. 路线：……
3. 讲授：……
4. 检测：……
5. 迁移：……
```

## 2. 加载顺序

1. 用户提到的学科命中 `SKILL.md` 学科表
2. 读取对应 `subjects/*.md`
3. 先看 `type`，再执行「执行微流程」
4. 微流程优先于通用 SOP 的默认节奏，但以下不可跳过：
   - Phase 1 学情诊断
   - 理解检查 / 刻意练习循环
   - 教学错误纠正
   - 诚实边界（不确定就说不确定）
5. 没有微流程的旧文件/自定义学科 → 回退到 `ref/teaching-sop.md`
6. 一个会话只加载当前学科；跨学科连接单独处理

## 3. 两种类型

| 类型 | 适用学科 | 教学主线 | 检测重点 |
|------|---------|---------|---------|
| knowledge | 数学、编程、语文、英语、物理、化学、历史、生物、AI | 概念 → 例子 → 练习 → 检测 → 迁移 | 能否理解并应用 |
| methodology | 费曼思维等思维方法学科 | 识别旧模式 → 制造冲突 → 新模型 → 场景练习 → 习惯固化 | 行为是否真的改变 |

### knowledge 的默认路径

```
诊断先修 → 概念/公式 → 例子/实验 → 练习 → 检测 → 迁移
```

- 讲解以"概念怎么来的、怎么用"为主
- 每个概念至少一个正例 + 一个反例
- 检测优先用新题，不用原例题

### methodology 的默认路径

```
识别旧模式 → 制造冲突 → 新模型 → 场景练习 → 习惯固化
```

- 不要先讲定义和知识体系
- 先让用户看见旧做法的问题
- 检测看行为是否改变，而不是复述名词
- 每个模型配一个日常触发点

## 4. 学科微流程速查

| 学科 | type | 微流程重点 |
|------|------|-----------|
| 数学 | knowledge | 诊断先修 → 直觉/推导 → 数值例子 → 数值题→符号题→证明 → 换场景重述 |
| 编程 | knowledge | 读代码预测输出 → 最小可运行程序 → 意图→代码→运行 → 改代码/调试 → 独立项目 |
| 语文 | knowledge | 阅读/文言/写作定位 → 字词→句段→篇章 → 文言三阶/先题干后文本 → 依据题 → 同题材迁移 |
| 英语 | knowledge | 听说读写小任务定位 → 语法→词汇→听说→读写 → 可理解输入→归纳→输出 → 改错/翻译/复述 → 换场景表达 |
| 物理 | knowledge | 生活现象诊断 → 现象→模型→公式→实验 → 建模+量纲检查 → 定性→定量→实验设计 → 真实场景建模 |
| 化学 | knowledge | 宏观/微观/符号三层诊断 → 性质→反应→方程式→计算 → 现象→微观→符号 → 配平/推断/计算 → 换物质重做 |
| 历史 | knowledge | 时间线/因果诊断 → 时间线→事件→人物制度→多视角 → 时间轴+因果链+史料 → 排序/因果/史料 → 同类事件比较 |
| 生物 | knowledge | 结构-功能配对诊断 → 分子→细胞→组织→器官→系统→生态 → 结构→功能→调节 → 识别/排序/机制 → 新场景解释 |
| AI | knowledge | 先问"会用/懂原理" → 概念→使用→原理→创造 → 类比+工具演示+能力边界 → 用工具完成任务并解释 → 业务场景工作流 |
| 费曼思维 | methodology | 说旧模式 → 反例制造冲突 → 一句话原则+检查清单 → 2-3 个新场景 → 日常触发点+复习卡 |

> 详细微流程见各 `subjects/*.md` 正文。

## 5. 新增学科

1. 复制 `subjects/_template-SKILL.md`
2. 填写 frontmatter：`subject`、`type`、`version: 4.0.0`
3. 写 5 步「执行微流程」
4. 在 `SKILL.md` 学科表加一行
5. 在 `config/skill-config.json` 的 `subjects` 中登记（可选）
6. 跑 `python -m unittest discover -s tests` 确认没破坏

## 6. 边界

- 学科微流程不能覆盖安全/诚实/纠错规则
- 不要同时套多个学科的微流程
- 学科文件只写"怎么教"，不写具体课程内容；课程内容由当前教材/资料决定
- 方法论型学科不要退化成"讲概念 + 刷题"
